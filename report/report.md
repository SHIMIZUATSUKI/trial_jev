# jevの能力を測定

実施日: 2026-10-14  
対象: TypeSafe Jev（`jev-latest`）  
比較対象: OpenAI Decisions API（`gpt-6-luna`）、OpenAI Chat Completions（`gpt-4.1-mini`）、TF-IDF + ロジスティック回帰

---

## 1. 検証概要

### 目的
ビジネスメールの **緊急度（high / medium / low）分類** というタスクで、TypeSafe Jev の **精度** と **応答速度** を、同じ種類の分類専用 API（OpenAI Decisions API）、汎用 LLM（GPT）、古典的なベースライン（TF-IDF）と同じ条件で比較する。

### 緊急度の定義（全モデル共通）
| ラベル | 定義 |
|---|---|
| high | 今日〜数時間以内の対応が必要 |
| medium | 数日以内の対応が必要 |
| low | 対応期限がなく、情報共有が中心 |

### データセット
- 日本語のビジネスメール **100件**（件名と本文。95〜220字、平均138字）
- 緊急度ラベル: high 33 / medium 34 / low 33
- 判断の難しさ（難易度）を、緊急度とは別の軸として3段階で付与した

| 難易度 | 件数 | 基準 | 例 |
|---|---|---|---|
| high | 20 | 件名や言葉が正解と逆を指す／重要な情報が末尾に埋もれている／控えめな書き方から状況を推し量る必要がある | 「お手すきの際にご確認ください」（SSL証明書が今夜切れる → 緊急度high）、「【緊急】件名のメール訓練について」（→ 緊急度low） |
| medium | 33 | 緊急ワードはないが、期限や影響を読めば判断できる | 「月末の支払いについて」（銀行の締めが15時 → 緊急度high） |
| low | 47 | 「至急」「本日17時」などの手がかりが、正解とそのまま一致する | 「【至急】ECサイトの在庫表示がすべて0になっています」 |

### 比較したモデル
| モデル | 方式 | 出力 |
|---|---|---|
| **jev** | TypeSafe Jev `system_one`。high/medium/low の Choice 質問 | 選んだ答え・確信度・各選択肢の確率 |
| decisions | OpenAI Decisions API。high/medium/low の choice 質問 | 選んだ答え・確信度・各選択肢の確率 |
| gpt | OpenAI Chat Completions（temperature=0、JSON モード） | `{"urgency": "..."}` |
| tfidf | 文字の1〜3文字の並びを TF-IDF で数値化し、ロジスティック回帰で分類。Leave-one-out で評価 | ラベル |

### 測定条件
- 全モデルで同じ100件を、1件ずつ分類した。
- API を使う3モデルは、クライアントを1つ作って使い回し、計測しない空打ちを1回してから計測した（接続準備の時間を除外して条件をそろえるため）。
- 時間は `time.perf_counter()` で、リクエストを送ってから答えが返るまでを測った。
- `--repeat 1`（各メール1回ずつ）
- 評価指標: 正解率、Macro-F1、難易度別の正解率、処理時間（平均・中央値・最小・p95・最大・標準偏差）

## 2. 結果

### 2.1 精度
| モデル | 正解率 | Macro-F1 | 難易度high (20) | 難易度medium (33) | 難易度low (47) | 誤分類 |
|---|---|---|---|---|---|---|
| **jev** | **1.00** | **1.00** | **1.00** | **1.00** | **1.00** | **0件** |
| decisions | 0.99 | 0.99 | 1.00 | 0.97 | 1.00 | 1件 |
| gpt | 0.95 | 0.95 | 0.95 | 0.94 | 0.96 | 5件 |
| tfidf | 0.86 | 0.86 | 0.85 | 0.79 | 0.92 | 14件 |

**混同行列**（行 = 正解 high/medium/low、列 = 予測 high/medium/low）

| | jev | decisions | gpt | tfidf |
|---|---|---|---|---|
| 正解 high | 33 / 0 / 0 | 33 / 0 / 0 | 33 / 0 / 0 | 30 / 3 / 0 |
| 正解 medium | 0 / 34 / 0 | 1 / 33 / 0 | 4 / 30 / 0 | 4 / 28 / 2 |
| 正解 low | 0 / 0 / 33 | 0 / 0 / 33 | 0 / 1 / 32 | 3 / 2 / 28 |

**API の3モデルの誤分類**

| # | 件名 | 正解 | gpt | decisions | jev |
|---|---|---|---|---|---|
| 052 | 面接評価シート提出のお願い（期限: 明日の終業時） | medium | high ✗ | high ✗ | medium ✓ |
| 053 | 顧客からの機能要望への回答について（期限: 今週金曜） | medium | high ✗ | ✓ | ✓ |
| 054 | 次期予算案の数値確認のお願い（期限: 来週月曜正午） | medium | high ✗ | ✓ | ✓ |
| 068 | ご確認ください（発注数量の食い違い、納品は来週金曜） | medium | high ✗ | ✓ | ✓ |
| 094 | 本日18時から全社懇親会です（任意参加） | low | medium ✗ | ✓ | ✓ |

**有意差の検定**（McNemar の正確検定。同じメールで片方だけが正解した件数を比べる）

| 比較 | 片方だけが正解した件数 | p 値 |
|---|---|---|
| jev と gpt | jev だけ 5 : gpt だけ 0 | 0.062 |
| decisions と gpt | 4 : 0 | 0.125 |
| jev と decisions | 1 : 0 | 1.000 |

### 2.2 処理時間（1件あたり、ms）
| モデル | 平均 | 中央値 | 最小 | p95 | 最大 | 標準偏差 | 合計 (100件) |
|---|---|---|---|---|---|---|---|
| **jev** | **187.1** | **179.7** | **152.3** | **235.3** | **250.7** | **20.4** | **18.7 秒** |
| decisions | 257.7 | 236.6 | 193.3 | 347.4 | 668.1 | 66.5 | 25.8 秒 |
| gpt | 719.0 | 686.1 | 514.6 | 1097.0 | 1628.2 | 179.9 | 71.9 秒 |
| tfidf | 2.0 | 1.9 | 1.0 | 3.1 | 4.1 | 0.6 | 0.2 秒 |

- jev は100件中 **94件で decisions より速かった**。
- 400ms を超えたのは、jev 0件、decisions 2件、gpt 100件。
- 文字数（95〜220字）と処理時間には、はっきりした関係は見られなかった。

## 3. 考察

### 3.1 精度: jev は全問正解。差がついたのは「期限があるが急ぎではない」メール
- jev は難易度high を含む100件すべてを正しく分類した。
- 言葉と正解が逆になっている「わな」のメール（「【緊急】件名のメール訓練」「Re: 契約解除の件（継続で合意済み）」「お手すきの際に（SSL証明書が今夜切れる）」など）は、API の3モデルがほぼ全部正解した。**文脈を読む能力そのものは、3モデルとも高い。**
- 差がついたのは **medium と high の境目** だった。gpt の誤分類5件のうち4件は、「今週金曜まで」「来週月曜正午まで」のように **期限が書いてあるだけで medium のメールを high と判定する過剰反応** だった。数日先の期限を、汎用 LLM は「急ぎ」と受け取りやすいと考えられる。
- jev と decisions は、選択肢ごとの説明（criteria）をもとに確率を出して選ぶ方式で、こうした境目のメールでも定義どおりに判定できていた。
- ただし、有意差の検定では jev と gpt の差は p=0.062、jev と decisions の差は1件で、**統計的に差があるとはまだ言えない**。今回の結果は「jev が精度で劣ることはない」という強い証拠ではあるが、「jev がほかより優れている」と言い切るには、境目のメールを増やした追加の検証が必要である。

### 3.2 速度: jev が最も速く、最も安定している
- 中央値で jev は decisions より約57ms（約24%）速く、gpt より約3.8倍速い。94/100件で decisions を上回っており、**速度の優位ははっきりしている**。
- 特に目立つのは安定性で、jev の標準偏差は 20ms と decisions（67ms）の約3分の1、最大でも 251ms だった。リアルタイムでメールを振り分けるような用途では、平均より最悪のときの遅延が問題になるので、この安定性は実用上の利点になる。
- gpt は文章を生成して JSON に整える分、時間がかかり、ばらつきも大きい。分類だけが目的なら、分類専用の API（jev / decisions）のほうが速度の面で有利である。

### 3.3 TF-IDF について
- TF-IDF の正解率 0.86 は、20件版で測ったときの 0.55 から大きく上がっている。学習データが増えたことに加え、例文に含まれるラベルごとの決まり文句（low の「対応いただくことはありません」など）を覚えた可能性があり、**文脈を理解した結果ではない点に注意が必要**である。
- それでも、文脈を読む必要がある難易度medium では 0.79 にとどまり、API の3モデルとの差ははっきりしている。

### 3.4 総合評価
| 観点 | 順位 |
|---|---|
| 精度 | jev ≧ decisions > gpt ≫ tfidf（API の3モデルの差は統計的には未確定） |
| 速度 | **jev** > decisions ≫ gpt（jev の優位ははっきりしている） |
| 安定性 | **jev**（標準偏差 20ms）≫ decisions（67ms）≫ gpt（180ms） |

今回のタスクでは、**jev は精度・速度・安定性のすべてで最も良い結果** だった。緊急度の分類のように「決まった選択肢から1つ選ぶ」タスクでは、汎用 LLM より分類専用の API が適しており、その中でも jev は速度と安定性で優れていた。

---

## 4. 限界と今後の課題
1. **データ**: 100件のうち80件は、生成 AI（Claude）が作成した例文である。正解ラベルと難易度も作成者の判断で付けており、#052（期限が「明日の終業時」）のように medium か high か判断が分かれるものがある。
2. **件数**: 精度の差は数件分で、統計的な結論を出すには足りない。medium と high の境目のメールを増やす必要がある。
3. **計測回数**: 各メールを1回ずつしか測っていない。`--repeat` で複数回測れば、時間の比較の確度が上がる。
4. **未比較の観点**: 料金、確信度（confidence）の当たり具合、もっと長いメールや英語のメールでの性能は、今回は比べていない。
